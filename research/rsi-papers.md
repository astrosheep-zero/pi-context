## Research scout: frozen-weight, context-carried self-improvement

Ranked by copyability for a TypeScript `pi` plugin. “Port” is my inference; mechanisms and results are sourced. **UNVERIFIED** means I did not find an official artifact supporting that detail.

| Rank | System | Verified mechanism and evidence | `pi` plugin sketch |
|---:|---|---|---|
| 1 | **ACE — Agentic Context Engineering** (2025/ICLR 2026) — [paper](https://arxiv.org/abs/2510.04618), [repo, Apache-2.0](https://github.com/ace-agent/ace) | An evolving, structured playbook updated by separate generation, reflection, and curation stages; it uses incremental updates to avoid “context collapse,” rather than repeatedly rewriting one summary. The paper reports “**+10.6% on agents and +8.6% on finance**” and “**reducing adaptation latency by 86.9% on average**.” | Store a versioned `playbook.md` as atomic, attributed rules; propose deltas after completed tasks, run a reflector against test/lint outcomes, then admit only validated deltas. |
| 2 | **Dynamic Cheatsheet** (2025) — [paper](https://arxiv.org/abs/2504.07952), [repo, MIT](https://github.com/suzgunmirac/dynamic-cheatsheet) | Persistent compact “cheatsheet” of strategies/code snippets, with three useful storage modes: cumulative, top-*k* retrieval plus synthesis, and their hybrid. The official repo describes these variants; the paper reports GPT-4o Game-of-24 success “**increased from 10% to 99%**,” Claude 3.5 Sonnet AIME accuracy “**more than doubled**,” and +9% GPQA-Diamond/+8% MMLU-Pro. | Maintain a small workspace-level “coding cheatsheet” plus embedding-retrieved successful incident packets; make it task-scoped and require a passing command before promotion—an omission in the research prototype. |
| 3 | **Agent Workflow Memory (AWM)** (2024; ICML 2025) — [paper](https://arxiv.org/abs/2409.07429), [repo, Apache-2.0](https://github.com/zorazrw/agent-workflow-memory) | Induces reusable workflows—common subroutines with example-specific context abstracted away—from annotated examples offline or prior trajectories online; it selectively injects them later. The paper reports “**24.6% and 51.1% relative success rate**” improvement on Mind2Web and WebArena; the official repo reports “**35.6% success rate**” on WebArena. | Extract named workflows such as “reproduce → localize → patch → targeted test → full check”; retrieve by task/repo/tool signature, not raw semantic similarity alone. |
| 4 | **A-MEM** (2025; NeurIPS 2025) — [paper](https://arxiv.org/abs/2502.12110), [system repo, MIT](https://github.com/agiresearch/A-mem), [evaluation repo](https://github.com/WujiangXu/AgenticMemory) | Zettelkasten-like notes: each write creates structured attributes, contextual description, keywords, and tags; it searches historical notes, creates semantic links, and can revise related notes. The official repo says it was evaluated on “**six foundation models**” and outperformed its baselines; its NeurIPS table also reports substantially shorter input context than full-history baselines. | Use typed notes (`failure`, `repository-fact`, `workflow`, `tool-quirk`) with backlinks and provenance; revise only affected neighbors after a validated contradiction, never wholesale rewrite the notebook. |
| 5 | **Mem0** (2025) — [paper](https://arxiv.org/abs/2504.19413), [repo, Apache-2.0](https://github.com/mem0ai/mem0) | Extracts salient facts from conversations, consolidates them, retrieves them dynamically; optional graph memory adds relational edges. Paper quote: “**26% relative improvements in the LLM-as-a-Judge metric over OpenAI**”; graph version is “**around 2% higher overall**”; it claims “**91% lower p95 latency**” and “**more than 90% token cost**” saved versus full context. | A pragmatic memory service adapter: extract durable repo/user facts, merge/update by entity key, retrieve only for relevant task phases, and attach a source-turn/test-run pointer to every fact. |
| 6 | **GEPA — Reflective Prompt Evolution** (2025; ICLR 2026) — [paper](https://arxiv.org/abs/2507.19457), [repo, MIT](https://github.com/gepa-ai/gepa) | Treats prompts, configurations, and text artifacts as candidates: sample traces, reflect on task-specific feedback, mutate candidates, and retain complementary candidates on a Pareto frontier. Paper quote: “**outperforms GRPO by 6% on average and by up to 20%, while using up to 35x fewer rollouts**”; it also reports “**+12% accuracy on AIME-2025**” over MIPROv2. | Run bounded offline evolution over `pi` skill text/tool instructions using a fixed regression suite; retain Pareto candidates by pass rate, token cost, and safety—not self-edit the live harness. |
| 7 | **TextGrad** (2024) — [paper](https://arxiv.org/abs/2406.07496), [repo, MIT](https://github.com/zou-group/textgrad) | A textual “autodiff” loop: evaluator feedback becomes a textual gradient, propagated to nodes in a computation graph, then an optimizer rewrites the relevant textual variable (prompt, code, etc.). It reports GPQA zero-shot GPT-4o “**from 51% to 55%**” and “**20% relative performance gain**” on LeetCode-Hard solution optimization. | Represent skill instructions and tool schemas as graph nodes; route compiler/test failure critiques only to the responsible node, then require evaluation before accepting the edit. |
| 8 | **AutoGuide** (2024) — [paper](https://arxiv.org/abs/2403.08978) | Generates concise, **conditional** natural-language guidelines from offline experience and selects guidelines applicable to the current context. Its paper reports better results than baselines across web-navigation tasks. **Official code/repository and license: UNVERIFIED.** | The simplest useful idea: store rules as `when <observable state>, do/avoid <action>, because <evidence>`; activate only when predicates match, which stops generic advice from poisoning every coding task. |
| 9 | **ExpeL** (AAAI 2024; paper first posted 2023) — [paper](https://arxiv.org/abs/2308.10144), [repo, Apache-2.0](https://github.com/LeapLabTHU/ExpeL) | Collects trajectories from training tasks, extracts natural-language insights, then recalls both insights and relevant experience at inference—explicitly without parameter updates. Its published per-environment table includes ALFWorld `put` success **83%** for ExpeL versus **50%** ReAct and WebShop reward **0.701** versus **0.665** ReAct. | Keep raw successful/failed coding trajectories separately from distilled advice; retrieve a few analogous incidents alongside a compact rule set. |
| 10 | **Reflexion** (2023 foundation) — [paper](https://arxiv.org/abs/2303.11366), [repo, MIT](https://github.com/noahshinn/reflexion) | After feedback, the agent writes a verbal reflection into an episodic buffer and retries with that text in context. Paper quote: “**91% pass@1**” HumanEval versus “**80%**” prior GPT-4. | Add a per-issue retry journal that converts test/compiler feedback into one actionable lesson; expire it when the issue closes or after a small retry budget. |
| 11 | **Voyager** (2023 foundation) — [paper](https://arxiv.org/abs/2305.16291), [repo, MIT](https://github.com/MineDojo/Voyager) | An ever-growing library of executable, composable skills; environment feedback, errors, and self-verification iteratively improve generated code. It bypasses fine-tuning. Reported results: “**3.3x more unique items**,” “**2.3x longer distances**,” and key milestones “**up to 15.3x faster**.” | Promote a successful multi-step coding routine into an executable `pi` skill only after deterministic verification; index it by inputs, side effects, and required tools. |
| 12 | **MemGPT / Letta** (2023 foundation) — [paper](https://arxiv.org/abs/2310.08560), [current official repo, Apache-2.0](https://github.com/letta-ai/letta) | OS-style virtual context management: the model explicitly moves information between memory tiers and can use interrupts/heartbeats to continue memory operations before responding. The paper validates it on oversized-document analysis and multi-session chat, but the fetched primary abstract gives **no precise benchmark number**. | Implement explicit tiers: small always-loaded project constitution, searchable archival history, and task-local scratchpad; tool calls—not implicit prompt stuffing—control promotion/eviction. |
| 13 | **MemoryBank** (2023 foundation; AAAI 2024) — [paper](https://arxiv.org/abs/2305.10250), [repo, MIT](https://github.com/zhongwanjun/MemoryBank-SiliconFriend) | Long-term storage/retrieval plus Ebbinghaus-inspired forgetting: retention is reinforced or decays based on elapsed time and importance. Its AAAI paper’s English probing results include **0.716 correctness** and **0.912 coherence**. | Assign every note a utility/confidence/last-confirmed score; decay speculative lessons, reinforce rules reused in passing tasks, and archive rather than silently delete. |

### Design synthesis for `pi`

The highest-value composite is: **AWM’s workflow unit + ACE’s versioned delta curation + Dynamic Cheatsheet’s compact/retrieved split + MemoryBank-style decay**.

A safe admission pipeline would be:

`raw history → candidate note/workflow → evidence link (test, lint, user correction) → scoped retrieval → promotion only after reuse/validation → decay/archive when stale`

That is materially safer than Reflexion/DC-style immediate self-promotion: those systems prove that context can improve behavior, but their default write paths often let unvalidated model text become instruction-like memory. Frozen weights are not the limitation here, little fish—the governance of what gets to become context is.
