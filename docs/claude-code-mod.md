# Claude Code Mod

The package also ships `mods/pi-context`, an early-access Claude Code Mod that registers the five notes tools as `mcp__pi-context__notes_*` tools and attaches one host-scoped notes boot block through Claude's conversation-scoped `prompt.context` event; Claude persists it across resume and reload. The sandboxed hooks module delegates filesystem and shared-domain work to the plugin-local `mods/pi-context/dist/claude/helper.js` through Claude's bounded `$.process.run` capability.

In interactive sessions it resets automatically when `$.session.usage().context.percent >= 85`, checking after `session.measure` and `turn.complete` and waiting for a running turn to complete. Missing percentages do not trigger a reset. Its own `session.compact` hook replaces the conversation with exactly one freshly built notes boot, not a generated summary. `prompt.context` still recomputes but does not duplicate that retained boot. Boot window IDs end in the ordinal `:0`, `:1`, etc.; retained boots restore the ordinal on resume/reload. Original transcript rows remain on disk.

`/clear-memory` requests the same reset. While idle it submits one hidden normal-model close-out turn to let the model save notes, then resets at `turn.complete`; while busy it waits for the current turn instead. This is necessary in Claude Code 2.1.295: `command.run` holds a turn, and calling compact from a detached timer skips the plugin's own compact hook. The timer only schedules the close-out prompt, never compaction. The headless (`-p` / SDK) compact capability is unsupported: automatic attempts are caught and logged once, and the manual command skips without submitting a model turn. Boot acquisition failure vetoes reset, leaving the current window intact. These behaviors add no settings. Claude history tools, Pi-style warning/runway budgeting, and a Claude dream backend are not implemented.

The plugin also exposes the shared `skills/dream/SKILL.md` and its referenced `playbook.md`; the build synchronizes both projections from the canonical repository files. Validate it from a built checkout with `claude plugin validate mods/pi-context --strict`; the package build and `npm pack --dry-run` include the manifests, hooks module, helper, skill, and playbook.
